¿QUÉ PASÓ CON EL SCRIPT ANTERIOR?
Tenía un bug mío (del dev): insertaba los 2 bloques de permisos
de los backups y DESPUÉS, al reemplazar el bloque del historial,
los PISABA sin querer. Resultado: publicó las reglas a medias y
encima terminaba diciendo "✅ ¡LISTO!" aunque su propia
verificación interna había fallado. Este v1.1 arregla las dos
cosas: ya no pisa nada, y si algo no queda, lo dice con ❌
grande en vez de un ¡LISTO! trampa.

¿QUÉ ESTABA PASANDO (el problema de fondo)?
Cuando tocabas "🏁 FINALIZAR Y GUARDAR RUTA", el historial SÍ se
guardaba (tus rutas de TODO este tiempo están ahi, tranquilidad),
pero:
  · El ☁️ backup de la nube NO subía → el toast te avisaba
    "⚠️ el backup de la nube NO se pudo guardar, avísame para
    revisarlo".
  · La pantalla ☁️ Backups salía VACÍA.
  · Y de yapa descubrimos que 📜 Historial, 📊 Estadísticas,
    💰 Caja e 🖼️ Galería TAMBIÉN veían todo vacío — por el mismo
    motivo (las reglas de Firestore no dejaban LEER la lista).

LA CAUSA (sin tocar tu app): las REGLAS DE SEGURIDAD de Firestore
nunca tuvieron los permisos para:
  · backups_v2 (donde va el backup del cierre + la pantalla ☁️)
  · usuarios/{tu-uid}/backups (el backup v1)
  · el LISTADO del historial (la regla vieja solo dejaba leer
    doc por doc, no la lista completa)

 CÓMO INSTALAR (2 pasos, 2 minutos)
═════════════════════════════════════════════════════════════

PASO 1 — PUBLICAR LAS REGLAS (lo importante):
  1. Copiá actualizar_reglas_backups.js a la carpeta del bot
     (el zip se descomprime ENCIMA de ~/bot-whatsapp):
       cd ~
       unzip -o descargas/robot-reglas-faseN-v2.zip -d ~/bot-whatsapp
  2. Corrélo:
       cd ~/bot-whatsapp
       node actualizar_reglas_backups.js
  3. Arriba de TODO tiene que decir:
       📋 actualizar_reglas_backups.js v1.1 (FASE N — fix del publicar a medias)
     (si no lo dice, estás corriendo un archivo viejo — el zip se
      te descomprimió en una subcarpeta)
  4. Al final tiene que decir:
       🚀 Reglas publicadas ✓
       ✅ Verificado → backups_v2 ✓ · usuarios/{uid}/backups ✓ · historial get/list ✓
       ✅ REGLAS PUBLICADAS Y VERIFICADAS (FASE N completo)
     Si en cambio sale un ❌ (aunque sea uno): NO pruebes la app —
     mandale captura al dev de TODO lo que salió en la pantalla.
  5. Si ya habías corrido el v1.0, vas a ver líneas "✅ ... ya está
     en las reglas vivas" para lo que ya quedó — es normal, este
     script completa lo que falta y no repite lo que ya está.

  Es el MISMO mecanismo que ya usaste para el robot de inDrive
  (actualizar_reglas.js v3.3) — mismo serviceAccount, mismo todo.
  Es IDEMPOTENTE: si lo corrés dos veces, la segunda salta todo.

PASO 2 — ACTUALIZAR LA APP (SOLO si todavía no instalaste el
v0.10.4):
  Instalá el APK nuevo (RiderTrackV2-v0.10.4.apk) encima del que
  tenés — como siempre, SIN desinstalar. Si ya lo tenés puesto
  cuando corriste el script v1.0, NO hace falta reinstalarlo:
  el APK es el mismo; lo que faltaba eran las reglas.
